# feat(tui): circular progress ring widget (arc + status color + blink)

## Overview

Widget puro de anel de progresso para o trilho de sessions: um arco preenchido sobre uma trilha escura, com a cor do status da session e ênfase de blink para estados de erro. Não sabe nada sobre sessions — recebe `(pct, status, theme)` e renderiza. As matérias-primas já existem e estão centralizadas: `session.context_pct: f64` em 0..1 (`src/session/types.rs:392`, já gauge em `src/tui/panels.rs:464`), `Theme::status_color(status)` para todos os 16 variantes de `SessionStatus` (`src/tui/theme.rs:659-678`), trilha escura via `gauge_background` (`src/tui/theme.rs:390`), e precedentes de blink no repo: `Modifier::SLOW_BLINK` para conflito e flash via `transition_flash_remaining` (`src/tui/panels.rs:380-392`). A técnica de rendering vem do spike {{s1}}.

## Expected Behavior

Semântica do anel (decidida aqui — o visual de inspiração pede "cheio=done, vazio=queued, meio=in-progress"):

| Estado | Arco | Cor |
|---|---|---|
| `Completed` | 100% (anel cheio) | `status_color` (azul) |
| `Queued`, `Spawning` | 0% (só trilha) | `status_color` |
| Todos os outros ativos (Running, GatesRunning, Interactive, Retrying, CiFix, ConflictFix, NeedsPr, NeedsReview, FailedGates, Stalled, Paused) | `context_pct` clampado a [0,1] | `status_color` |
| `Errored`, `FailedGates`, `Killed` | `context_pct` + `Modifier::SLOW_BLINK` | vermelho (`status_errored`) |

Arco = contexto, cor = status, blink = falha. Um canal por sinal: a % de contexto continua visível no painel da célula (`src/tui/panels.rs:464`) — o anel é olhar rápido, não medidor preciso.

## ADR stub

Bifurcação: (a) arco = `context_pct` sempre, cor = status — honesto, mas um `Completed` com 80% de contexto NUNCA aparece cheio e contradiz o visual pedido (cheio=done); (b) arco = tabela de semântica de estado (Completed=100%, Queued=0%, ativos=contexto) com cor = status — casa com a imagem de inspiração e mantém um canal por sinal; (c) arco = "progresso de tarefa" sintético — rejeitado, maestro não tem % de tarefa e inventar uma é fabricação. Recomendação (para discordar): (b), com a tabela acima como contrato testado.
