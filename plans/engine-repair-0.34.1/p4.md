Measured 2026-11-27 (tmux capture, nightly `30f3b1d8`): opening the TUI on a repo with 3 completed session records in `maestro-state.json` and 4 open maestro-created PRs on GitHub shows Dashboard `Work (0)`, `SESSIONS 0`, and the empty-state copy `○ No PRs waiting. Finished work shows up here.` rendered by `crates/maestro-tui/src/tui/screens/dashboard/draw.rs:185`, plus a header spend of `$0.00/50` while the state file carries non-zero cost. The TUI reads only its own process memory; persisted sessions and the repo's open PRs never reach the surface. The promise in the empty state ("Finished work shows up here") is false, and a user returning after headless runs sees a dead product.

## Reprodução

1. `maestro run --once --issue N` (completes, opens a PR); confirm `gh pr list` shows it and `maestro-state.json` has a session record.
2. Open `maestro` (TUI) in the same directory, go to `2 Dashboard`.
   Saída observada (a real, não a esperada): `SESSIONS 0`, `PR PIPELINE 0`, header `$0.00/50`.
