Measured 2026-11-27 on the lab: two `team launch` runs reported `0 succeeded, 2 failed` — and the lab's MAIN checkout was left with 76 uncommitted inserted lines across `todo.py`, `tests/test_todo.py`, `README.md` (the exact scope of the "failed" issue #2; residue preserved in `plans/session-followups/team-residue.patch`). Cause: `dispatch_subagent` (`crates/maestro-core/src/orchestration/dispatch.rs:162`) builds the request without any worktree — the captured spawn ran with `cwd` = the invoking checkout — so a subagent whose RESULT is discarded as malformed has already applied its file edits for real. Side effects land, the report says nothing happened, and nothing records the change: silent writes plus a false report, the worst combination on the owner rules (no lost work / never a false UI promise).

## Reprodução

1. `git status --porcelain` in the project → clean.
2. `maestro team launch default-coder --issue N --yes` (fails per {{p1}}, or any subagent failure after edits).
3. `git status --porcelain` again.
   Saída observada (a real, não a esperada): ` M todo.py`, ` M tests/test_todo.py`, ` M README.md` — 76 inserted lines in the main checkout, while the command printed `0 succeeded, 2 failed` and the state file gained no record.
