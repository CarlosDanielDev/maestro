Measured 2026-11-27 on the lab: issue #1 already had open PR #4 (from an earlier era) when `maestro run --once --issue 1` completed. The session implemented the feature, committed `fa0f791` on `maestro/issue-1` — and nothing happened next: no push (the remote branch kept the old head `3c5b930`), no update to PR #4, no new PR, `pending_prs` stayed empty, and the run summary said `COMPLETED` without a word about the stranded commit. The existing-PR detection exists — `crates/maestro-tui/src/tui/app/auto_pr_apply.rs:82` logs `PR already exists for branch … — see …` — but the `--once` completion never surfaced it and never pushed. The work survived only because teardown keeps branches. Silence here violates the same owner rule as {{p2}}: work exists, the report says nothing.

## Reprodução

1. Open a PR whose head is `maestro/issue-N` (or any prior maestro run for issue N).
2. `maestro run --once --issue N` → session completes with new commits on `maestro/issue-N`.
   Saída observada (a real, não a esperada): local branch ahead of the remote, no push, PR untouched, summary silent; `git log origin/maestro/issue-N..maestro/issue-N` shows the new commit.

## ADR stub

Update the existing PR vs open a sibling branch+PR. Recommendation: update — one issue, one PR; a second PR for the same issue is the double-spawn sin in PR form. One fork.

## Out of scope
