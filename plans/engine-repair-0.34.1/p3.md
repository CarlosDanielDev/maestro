Two measured lies in cost reporting on nightly `30f3b1d8`:

1. Lab PR #10 body says `**Cost**: $0.00`; the session's real cost was $0.03. The session log shows the mechanism: `COST: $0.03` on one line and `COMPLETED: $0.00` two lines later (`.maestro/logs/4c217535-*.log`, 2026-11-27T16:15:45–46) — the completion path records a zero where the accumulated cost should be, and the PR body's Cost Report section (`crates/maestro-core/src/provider/github/pr.rs:21`) is generated from that zero. Owner rule: never a false promise — a generated artifact with a wrong number is worse than no number.
2. `maestro-state.json` `total_cost_usd` measured going DOWN between two runs: 0.0737 after the 3-issue run, 0.0245 after the next single run — the "total" is rewritten per process instead of accumulating.

## Reprodução

1. `maestro run --once --issue N` on a repo with `auto_pr = true`; wait for the PR.
2. `gh pr view <pr> --json body --jq .body | grep Cost`
   Saída observada (a real, não a esperada): `- **Cost**: $0.00` while the run summary printed `$0.03`.
3. Note `total_cost_usd` in `maestro-state.json`, run one more session, read it again.
   Saída observada: the value drops to roughly the last run's cost instead of growing.

## Done when

- [ ] the PR body prints the exact line `- **Cost**: $X.XX` with the session's accumulated cost — `pr_body_carries_session_cost` test passes with a stub provider reporting known usage and asserts the exact copy of the rendered line — owner: implementer
- [ ] the completion record never carries $0.00 when usage events reported non-zero cost — `completion_cost_matches_usage_events` test passes — owner: implementer
- [ ] `total_cost_usd` is monotonic across runs — `total_cost_accumulates_across_runs` test passes (two sequential runs, second total ≥ first) — owner: implementer
- [ ] an unpriceable model still renders `$?`/unknown, never `$0.00` (#1155 semantics preserved) — existing `cost_unknown` tests stay green — owner: reviewer

## ADR stub

Where the fix lands: at the completion event (carry accumulated cost) vs at the PR renderer (recompute). Recommendation: the event — every consumer downstream of `COMPLETED` gets the right number at once. One fork.

## Out of scope

- Per-wave/per-seat telemetry surfaces (v0.41.0 engine epic — the token-proof issue).
- Backfilling wrong costs in already-open PR bodies.
