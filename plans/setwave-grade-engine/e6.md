The 0.34.1 patches make the team engine WORK (transport {{p1}}, isolation {{p2}}); this slice makes it WORTH USING. Measured gap between maestro's two engines on 2026-11-27: the single-run path sends a rich prompt (full issue body, acceptance criteria, safety guards, unattended-mode note — captured verbatim from the session record) inside an isolated worktree with gates; the team path sends the one-liner `Implement issue #N and return CodeChange.` (`crates/maestro-core/src/orchestration/primitives/pipeline.rs:44`) with no issue content, no schema explanation, no worktree (spy-captured cwd = main checkout), and dispatched a blocked issue the run path refused. The L2 design intended an orchestrator that writes rich per-role instructions (`crates/maestro-core/src/orchestration/orchestrator.rs:53`); the headless path replaced it with a deterministic machine emitting stubs.

## ADR stub

Keep the primitive state machines (pipeline/fan-out/verdict-only) with real prompts vs collapse team launch into N single-run sessions with role addenda. Recommendation: keep the machines (the L2 contract types are sound), replace only the instruction builders and the spawn seam. One fork.
